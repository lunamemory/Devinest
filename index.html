Message Buddy and Dev Buddy are complementary workflows. Both use the same work memory, authorized connections, and project context.

Message Buddy

Dev Buddy

Turn intent into Jira.
Turn Jira into reviewed code.

Describe a feature or hand over an existing Jira issue. Dev Buddy retrieves domain and repository context, creates or enriches the work document, and coordinates development and independent review.

Jira keeps the outcome, constraints, repositories, and acceptance criteria together, so development and review can work from the same request.

Personal assistance. Deliberate data choices.

Private context.
Across your work.

Keep work memory in your own workspace, choose connected sources, and stay in control of messages and development actions. Local storage and a local classification default support that personal approach.

Keep your context on your Mac

Work memory lives in local mem0, with local embeddings by default. Devinest does not require a separate cloud memory store for this setup.

Process messages locally by default

The default inbox setup uses a local oMLX model to classify messages. Surface requests and priorities without requiring a remote model for that step.

Choose the scope. Review the result.

Select sources and history dates. Review outgoing replies and development results. Sending messages, merging code, and releasing changes follow their own authorization steps.

Understand where data goes

Local storage is one part of the privacy picture. Your connections and chosen AI model still define the rest.

Your connected providers

Email and chat stay subject to their providers, enterprise policies, and your account permissions. Authorized reads use those existing connections.

Your local Devinest runtime

Memory, inbox records, and task state are stored locally. Default embeddings and message classification use local oMLX models.

Your chosen AI host and model

Content used for reasoning, investigation, or reply drafting may be sent to the model endpoint configured in your host. Remote inference, when configured, also sends its input to that endpoint.

Message Buddy and Dev Buddy share the same foundation

Message Buddy handles messages, context checks, reminders, and reviewed replies. Dev Buddy turns requests into Jira work documents and coordinates implementation, independent review, and PR handoff. Both use shared local memory and authorized connections; the active AI host provides tools and execution.

Memory on your machine

The default uses local mem0 and oMLX embeddings. Host model inference is a separate data path; network use depends on your chosen host and model configuration.

Background and live facts

Memory recalls background. Jira, Git, and the code host remain authoritative for current task, code, and delivery state.

Existing permission boundaries

Connections stay within authorized scope. Replies require specific approval; merges and releases are separate decisions. A queued action is not a completed action.

Prefer the terminal? Manual installation

For Apple Silicon macOS. You need Git and Python 3, plus uv or Homebrew. Installing a missing oMLX requires Homebrew.

Terminal · Install for Codex
git clone --branch main https://github.com/lunamemory/Devinest.git
cd Devinest
python3 skills/devinest/scripts/bootstrap.py \
  --source "$PWD" --target codex \
  --install-uv --install-omlx --background

Run these commands in your terminal. The installer reuses existing configuration and memory, installs missing tools when supported, and starts the local console as a login service. Model preparation happens during setup.

Configuration and maintenance
  • Configuration: ~/.config/devinest/config.yaml
  • Setup: http://127.0.0.1:8790/setup
  • Health check: uv run devinest doctor
  • Service status: uv run devinest service status
  • To update an existing, different Skill, add --update to the installer command. Backups are preserved.
